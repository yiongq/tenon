# 循环接口的可执行模型

两个互相独立写的状态机模型，照 [spec.md](../spec.md) §主进程与 kernel 的循环接口 及相关节（§插话与输入框状态表、§答复与投递、§续跑、§进行中、暂停与 RunRegistry、§启动恢复与发送防护、§执行日志与恢复表、§交接、§停止、新消息、退出与重启）的**字面**写成，用广度优先把有界的事件交错走遍，查不变量。纯 Node，无依赖。2026-09-25 起草时用它们做了六轮核查，定稿时两者都是 0 违例。

- `model1/`：侧重根会话——租约、mailbox 次序、排队、立即发送、urgent、held、各状态下的停止、关窗与退出。`node run.cjs all 3`（13 个起始场景，每场景最多 3 次用户操作；约 190 万个状态）。
- `model2/`：侧重答复、续跑、启动后的可续跑项与子 agent 链。`node --max-old-space-size=8000 model.cjs 6`（深度 6，约 124 万个状态），输出 JSON，用 `node show.cjs <文件>` 看违例。

查的不变量（两边各自实现）：每个根会话最多一份活租约；没有租约的 Run 不发请求；排队消息不丢、不重复、按规定次序发出；返回 `stopped: true` 的停止一定收掉它看到的卡或可续跑项；启动时 0 次模型请求；缺 key 什么都不写；held 时对未确认主机 0 次请求；父子会话的等待状态一致；一个暂停的 Run 最多被一个 Run 续跑；没有死锁。

**什么时候跑**：改这些规则（spec 或 kernel `loop/` 的实现）之前先把模型改成新规则的字面，两个都跑到 0 违例再动 spec；实现第 9 步起的并发测试可以照模型的场景与不变量写。模型里的行号注释指 2026-09-25 的 spec，之后会漂。

**开关**（环境变量，用来重放某一轮修之前的写法，确认不变量仍能抓到它）：`PAUSED_NO_RECHECK=1`（第 5 轮）、`PRE_R6_STOP=1`（第 6 轮）、`CHILD_NO_RECHECK=1`（第 4 轮），`KEYCHAIN_HANG=1` 让钥匙串永不应答。例：`PRE_R6_STOP=1 node --max-old-space-size=8000 model.cjs 6` 应报 1 个违例。
