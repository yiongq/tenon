- **P1 · srt 的基本面与违规行**（macOS 沙箱外；Linux 随 P5）。按 spec §档位到 srt 配置 与 §argv、shell、env 与 id 的拼法 initialize（空白名单、strictAllowlist、`parentProxy: { noProxy: '*' }`、第三个参数为真）并 wrap：工作区外写、读 denyRead 里的文件、写不存在的 denyWrite 路径、连白名单外主机名、连 IP 字面量、不经代理直连、白名单里写 `localhost:<端口>`（强制走代理与认 `NO_PROXY` 的 curl 各一次，`curl --noproxy '' -x "$HTTP_PROXY"` 与默认）、`chmod 700` 测试主目录、触发一条 mach-lookup 类拒绝；macOS 另写 `.ENVRC`、`.Claude/settings.json` 这类大小写变体（工作区根下事先不存在），并在 workspace-write 下于工作区根 `git init`、往子目录 `git clone` 一个本地仓库（记成败，结论写进 spec 已知限制那一句）；主进程环境设 `HTTPS_PROXY` 后连一个解析到回环的白名单主机名，确认 `noProxy: '*'` 下仍被解析地址检查拒；记每条违规的原文行。同时核：返回的 argv 里带 srt 的变量（macOS 是 `env …`，Linux 是 `--setenv`）、返回的 env 就是 `process.env`（T6）；`binShell` 传绝对路径时内层 shell 就是它（T7）；另在 Claude Code 的沙箱里跑一次自检，记退出码与 stderr（读法 4 的 `nested-sandbox` 判据）。**决定**：行格式与 spec §afterExit 的表一致 → 照表写分类，原文行存成 `apps/desktop/test/sandbox/fixtures/violation-lines.json`；分不清「白名单外」与「解析到受限地址」→ 所有网络违规都不给域名按钮（保守），spec 记一条 Revisions；嵌套沙箱的退出码不是 71 → 按实测的码与 stderr 改判据；大小写变体写得进去 → macOS 加不分大小写的 glob（spec §档位到 srt 配置），写不进去 → 不加；`noProxy: '*'` 下解析地址检查没做 → 停下写 Open。保守分支（虚拟机里抓不到 Linux 的行时）：Linux 的夹具行照 srt79 的源码拼——观测器 `deny <系统调用> <路径>`（dist/sandbox/linux-violation-monitor.js:77）、代理 `deny network-outbound <host>:<port> (<原因>)`（sandbox-manager.js:170）——标「待实抓」。
- **P2 · 违规的到达时间与噪声**（macOS 沙箱外、CI 的 macOS runner；Linux 随 P5）。被拒的写与被拒的连接各 50 次，量「进程退出」到「违规进 srt 的存储」的间隔；在 workspace-write 档跑 `git status`、`node -e 1`、`python3 -c 1`、`npm -v`、`ls`、`cat`、`rg --version`，记有没有并非真拒绝的噪声行。Linux 另核观测器报不报工作区里的正常写（srt79 README.md:461），并在 workspace-write 下跑一次 `npm install <小包>` 数事件量；再在主进程 cwd 分别为 `/`、主目录与一个空目录时量一次 wrap 本身的耗时（srt 每次 wrap 从主进程 cwd 起跑 rg，linux-sandbox-utils.js:265-330）。CI runner 那次放在第四段 PR 的临时 job 里。**决定**：`VIOLATION_SETTLE_MS` = 本机与 CI 两处实测 p99 的较大者向上取到 50 ms 的倍数；超过 500 → 停下写 Open（选项：经 Revisions 提高上限，或黑盒用例经只在测试里用的轮询读违规、产品照旧）；噪声行按子串进 `ignoreViolations`（initialize 时就定死，之后改不了）；数字与名单写进 spec Revisions。观测器报工作区内的写 → 读法 11 的过滤必须做（照 spec）；不报 → 照做（无害）。cwd 为 `/` 或主目录时 wrap 比空目录慢出 500 ms 以上 → 停下写 Open（候选：initialize 之前让主进程 chdir 到 profile 之外的一个空目录，要先核对主进程里依赖 cwd 的读取），spec 记 Revisions。

- **P4 · 「包管理器」预设**（Q10 A；两平台）。先验 npm（开放问题 5 A，spec 读法 46–48）：白名单只放 `registry.npmjs.org`；probes/ 下一个代替 `<userData>/sandbox-cache/npm` 的目录进 allowWrite、命令环境设 `npm_config_cache` 指向它；临时 HOME 下放一个有内容的 `.npmrc` 并照凭据清单 denyRead，工作区里放一个写了 `cache=<别处>` 的 `.npmrc`。在临时工程里 `npm install <小包>` 与 `npx -y <小包>` 都成功，`_cacache`、`_npx`、`_logs` 都落在那个目录里，临时 HOME 的 `.npm` 下除 `_logs` 外没有新东西；macOS 上再在沙箱里把那个目录删掉、换成指向临时 HOME 下别处的同名链接，记成败（读法 48 的前提）。再逐个试 pnpm、yarn（classic 与 berry）、pip、uv、cargo、go：从空白名单起，按被拒的违规逐个加域名，直到装上一个小包；记最少的域名与要写的缓存目录（两个平台路径不同的分开记）。**决定**：一个管理器进预设，当且仅当装得上、所需域名都归包仓库的运营方（不含通用 CDN、任意对象存储）且不超过 4 个，并且照 spec 读法 49 只放开 Tenon 自己的缓存目录：能用一个环境变量把缓存挪到 `<userData>/sandbox-cache/<管理器>`，你自己的缓存目录与沙箱外的进程会直接执行的东西（`~/.cargo/bin`、`~/.cargo/env`、uv 的工具目录这类）一概不放开；记下那个变量，进了预设的照读法 47 加进 env、spec 记 Revisions（连同不变量 3）；不满足的不进、写明原因。npm 装不上、写进了 `~/.npm` 或 `cache=` 盖过了环境变量 → 停下写 Open；那个目录在 macOS 上换不成链接 → 读法 48 的核对照做（无害）。结果写进 spec Revisions 与预设常量（第 13a 步）。保守分支：只有 npm。

- **P6 · 停止与后台进程**（T11；两平台）。一条命令：`sleep 600 &`、`python3 -c 'import os,time; os.setsid(); time.sleep(601)' &`、前台 `sleep 602`，每个带唯一标记；第二条双重 fork 出一个睡眠进程后 `exit 0`；第三条 setsid 出一个睡眠进程（握住再关掉 stdout）后 `exit 0`。按 Bash 的停止序列（SIGTERM、`STOP_TERM_GRACE_MS`、SIGKILL 进程组）停第一条，1 秒后在宿主的 `ps -axo pid,args` 里找标记；第二、三条在正常退出、对进程组 SIGKILL 之后找。另试一次：每次 wrap 往命令环境注入一个标记变量，按它在宿主上找残留（macOS `ps -E`，Linux 读 `/proc/*/environ`）。**决定**：Linux 全无残留 → 照 spec；有残留 → 停下写 Open（与 spec 的前提不符）。macOS 上停止时 setsid 的有残留 → desktop 的 `killTree` 在发信号之前先按 `ps -A -o pid=,ppid=` 收集整棵子孙树、逐个再杀，spec 记一条 Revisions、验收 15 照原文；正常结束后 setsid 的有残留（父进程已退、树遍历找不到）→ 标记变量那法找得到就用它杀，找不到就把验收 15 与不变量 13 的正常结束半句在 macOS 上限定为同一进程组、写进已知限制；双重 fork 被 launchd 收养的照 spec 写进已知限制，验收 15 的用例不含它。每种情形在两个平台各起哪些进程，写进实施记录。
- **P7 · SIGKILL 后的挂载点**（T9；Linux）。工作区根下 `.envrc`、`.claude/settings.json` 都不存在；起一条 `sleep 30` 的沙箱命令，运行中看宿主上这两个路径；对 bwrap 与跑 srt 的进程都发 SIGKILL，再看；再起一个新进程 initialize，跑一条同配置的命令并正常结束，再看（0.0.79 不在 initialize 时清，而是在下一次拒同一路径的 wrap 里认出空的只读文件、收掉，linux-sandbox-utils.js:2087-2106；空目录认不出）。**决定**：只剩空目录（如 `.claude/`）→ `DesktopSandbox` 每次 wrap 前把「不存在、将被造成目录挂载点」的中间路径记进 `<profile>/sandbox/stubs.json`，下次启动时删掉其中仍是空目录的、清空记录（spec 记 Revisions，第 5 步加一条用例）；什么都不剩 → 不做。保守分支：不做，写进已知限制（spec 已写）。
- **P8 · 信号**（T4、srt-m6；macOS 沙箱外）。先在 probes/ 里用一个最小的 Electron 44 主进程脚本（装 `electron@44` 与 srt，`app.on('before-quit')` 里打日志、调 `reset()`）initialize 之后对它分别发 SIGTERM、SIGINT，看 before-quit 是否走到、5 s 内是否退出、reset 是否被调；接线之后在第 14 步用真应用再核一次。注意 srt 的两个监听是 `once`、回调就是 `reset()`：第一次信号之后代理已拆、配置还在。**决定**：不退出 → initialize 之后自己注册 `process.on('SIGTERM' | 'SIGINT')` → `app.quit()`，验收 3 加一条用例；退出但没走 before-quit → 接受、记一条（reset 没跑，挂载点照 P7）；正常 → 什么都不加。三种情形下 host 都在信号之后把姿态记不可用（spec §退出）。
