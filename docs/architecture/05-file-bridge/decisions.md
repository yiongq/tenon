- A 卡上不承诺：可逆性仍只看工具和参数（Write 未知、Delete 撤不回），拍成之后才在工具行和小结显示。代价：06 的自动档没法按「有快照」免问，2026-10-09 已定的自动档行为（D11、D23）做不到。

### D4 · 影子快照用哪个 git

### D5 · 第一张整树快照很慢、或文件夹大到拍不动时怎么办

题目原文：「05·D5：第一次整树快照很慢（1 万文件约 8 秒，5 万约 46 秒），之后每次只要零点几秒。第一张还没拍完，或者文件夹大到拍不动时，写文件和跑命令怎么办？」

- A ★ 后台拍，超预算就降级：首张后台拍；拍完前文件工具用单文件副本、命令照跑并在小结标明；预算首张最多 2 分钟或 10 万个文件，之后每次最多 5 秒；超了本会话只留单文件副本，告诉用户一次。代价：首张拍完之前、或降级之后，命令的改动还原不了。
- B 拍不成就不跑命令。代价：大文件夹里每条命令都被快照拖住或拒绝。
- C 照跑，只在小结标明，不设预算。代价：没有上限，大文件夹里每条命令前都可能卡很久。
- 选错难退吗：不难，预算是常量。
- 结果：owner 选 A · 2026-10-23（问卷，另记）。题干里的 macOS 数字是在另一个 agent 的沙箱里测的；同日沙箱外复测，5 万文件首张约 34 秒、之后每张约 0.13 秒（P1）。预算数字不据此改。「10 万个文件」数的是排除之后要进快照的文件（D53）。

### D9 · 「mtime 守卫」指什么

- A ★ 原文：「两处都做——① Write / Edit 写之前比对本会话最后一次读或写时的 mtime 与大小，变了不写、回给模型「请重读」（点名 (ii)）；② 还原时按快照之后记下的内容哈希逐文件比对，对不上逐个问「覆盖 / 保留」；mtime 用 utimes 写回、验收按微秒比；HostFs 只增 `utimes`。」代价：模型没读过就整篇写的文件不受 ① 保护。

### D49 · 还原怎么动文件

- A ★ 确认后重拍还原前那张、重算清单，与你看过的不符就 `stale`；还原前那张拍不成或没收全就拒绝。先删（深的先）再放回（浅的先）；大小写不敏感的卷上折叠后同名的一删一放当一项改名。每个路径：比一次 `identity`，变了就跳过；父目录的真实路径在文件夹真实根之下、中间没有链接；叶子 `O_NOFOLLOW`；新建 `O_CREAT|O_EXCL` 加起点的权限位；替换用同目录临时文件加改名；有多个名字的、不在当前工作区文件夹里的跳过。请求带 `overwrite`（必须是冲突的子集），没列的冲突一律保留。同一个真实文件夹上任何会话有进行中的 Run 时拒绝。每个影子仓库一把锁；进行中的轮、每个会话最近一轮不被清；启动时结束上次的 git 进程组、按最近一张重建索引；有开始没结束的还原，下次启动提示一次。代价：还原慢一点，规则多。

### D58 · 读文件时的印记、守卫判「不在」后的新建，要不要给接口加东西
