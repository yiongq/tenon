# ADR-004：接入 sdd v2

- **状态**：按 owner 已批准的差异卡接入
- **日期**：2026-10-22
- **背景**：Tenon 已有手工 SDD、共享 hooks 与 CI；本次采用 sdd 2.0.2，项目默认 standard，权限、沙箱、凭据、Tape、提示层按单份 spec 升 heavy。

---

## 决策

采用 sdd v2 的「已有 SDD」接入方式：核心块与受管区使用 skill 原文；旧 spec / plan 正文保持，接入前的不合规登记为 known。安装提交落地后，再登记 baseline_commit。

| 卡 | 卡题 | 选项 | 理由 |
|---|---|---|---|
| A1 | 重复、冲突的流程条文 | A（★） | 以 v2 核心块和受管区为唯一出处，Tenon 独有规则挪入本项目补充。 |
| A2 | 05 起页头及反向页头的写入时机 | A（★） | 统一用 Changes / Changed by / Approved，反向行与起草新 spec 同一个 PR 写入。 |
| A3 | 复杂 bug 的目录 | A（★） | 使用 docs/features/fix-<名>/，不建尚不存在的 docs/issues。 |
| A4 | plan 的额外节与尾步 | A（★） | 保留开工前读、分段、命令，记录移到 log，最后一步固定为 owner 验收 → 改 Status。 |
| A5 | claude-5-5-models 接入后如何做完 | A（★） | 后续实施按 v2 页头、log 和测试点名检查做完，本次不改它的 spec 或 plan。 |

## 规则改动

删除与 v2 重复或冲突的旧流程条文，项目特有约束保留在核心块外或本项目补充；硬规矩仅补守护标注，权限决策引用加后续 spec 的阅读指引；更新门禁说明与 owner 合并路径。依据为下面逐字记录的 owner 指令。

## owner 原话

> adopt A1–A22、N1a–N1c 按推荐；A6=A；A7=A；A8=A；A22=A；N1b=A

> 改好了， b,笔记照推荐，可以 git init

出处：对话（2026-10-22）。第二句里的「b」是 A9「给谁用」的选择（候选 b：想要一个开源、可自己掌控的 Claude Desktop 式桌面工作台的人）；「笔记」指私有笔记的事，不在本仓库。上表只记录本仓库的接入决定。
