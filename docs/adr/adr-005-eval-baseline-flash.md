# ADR-005：评测基线列换成 glm-5.3-flash

- **状态**：owner 已选定
- **日期**：2026-10-25
- **背景**：02 §同题对比 写的是「基线（每题都跑）：智谱的基线模型，走 `/paas/v4`，是验收基准；基线模型由小横评定」。2026-09-28 的小横评选了 glm-5.3：通过率 15/15，glm-5.3-flash 13/15，flash 掉的两次都是多步任务里的恢复，连着三次撞上被禁的工具（02 plan 第 25 步记录，那条记录也写了「owner 想改回 flash 只改这一行」）。之后每升一次提示层版本，都要在基线列上跑全集、每题 3 次：第 11 版（04 plan 第 15a 步）花了 ¥45.07。owner 嫌每做一个功能都要花这么多，要先查能不能用免费模型（原话见文末）。

---

## 调研（2026-10-25）

- **免费模型有**：智谱 [API 价格页](https://docs.bigmodel.cn/cn/guide/start/pricing) 把 GLM-4.7-Flash、GLM-4-Flash-250414 等列为免费；[GLM-4.7-Flash 模型页](https://docs.bigmodel.cn/cn/guide/models/free/glm-4.7-flash) 写了支持 Function Calling。[速率限制页](https://docs.bigmodel.cn/cn/api/rate-limit) 只说并发上限按模型分设、与账户等级有关，超了回 1302，平台过载回 1305，没有具体数字。
- **实测**（仓库外的临时副本，第 11 版提示层，题 01，各 1 次）：GLM-4.7-Flash 第一轮正确发出 Bash 调用，两次都在第二个请求上收到 429 / 1305「该模型当前访问量过大」，重试 3 次后整题失败；GLM-4-Flash-250414 能跑完，但修一个小 bug 时对同一处来回 Edit 二十多次也没修好。前者是服务商拒绝，后者是能力不够，都没法当回归的标尺。
- **价格**：按第 11 版基线的真实用量（60 次：输入约 282 万、缓存读约 964 万、输出约 11.5 万 token）换算，glm-5.3 ¥45.07（与记录一致），glm-5.3-flash 约 ¥4.80，glm-5.3-flashx 约 ¥11.94。

## 决策

基线列（`apps/desktop/evals/models.ts` 的 `BASELINE_COLUMN`）从 glm-5.3（`/paas/v4`）换成 glm-5.3-flash（`/paas/v4`）。同模型列、主对比列不变。

- 换列的同一个 PR 里，在 flash 上补跑第 11 版全集、每题 3 次，结果记进 `docs/evals/results/`，作为下一版逐题对照的参考。
- 之后每升一次提示层版本，照旧在基线列上跑全集、每题 3 次，逐题对照上一版；有题从过变不过就停下交 owner。
- 只比同一列的相邻两版，不拿 flash 的结果去和 glm-5.3 的旧记录比。

## 代价

- flash 比 glm-5.3 弱，弱在多步任务里的恢复。偶发失败会多一些，逐题对照时「从过变不过」的误报也可能更多，lead 照旧逐条看记录再判断，拿不准的交 owner。
- 每次升版本的花费从约 ¥45 降到约 ¥5；第一次换列多跑一轮第 11 版，约 ¥5。

## 不选的

- **免费模型**：GLM-4.7-Flash 会被过载拒绝，GLM-4-Flash-250414 能力不够（见调研）。智谱的免费模型以后稳定了，可以再评一次。
- **照旧用 glm-5.3**：每次约 ¥45。
