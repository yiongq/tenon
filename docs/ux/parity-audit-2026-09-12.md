# UX 对齐审计（2026-09-12）

Tenon 的 33 张画板与 Claude Desktop 的 183 张 fixture 大纲 + `interactions.md` 逐项对照的结果。做法：按界面分 8 组、按块词汇分 3 族，每组派一个 agent 对照一遍，再复核一次（复核结论：除「DarkCowork 整板」是 CoworkSession 的暗色副本外，其余全部成立）。

结论：**页面结构差异 128 条**（含 1 条重复，实为 127）、**块词汇 56 条**。

这份文档的用法：

- 它是**实现阶段的对齐清单**，不是设计稿。第 3 节按画板列页面级差异，第 4 节按块列消息流组件规格（给 assistant-ui 组件实现看）。
- **Claude 与 Tenon 完全相同的页面、菜单、弹层，以 fixture 为规格**，画板不再画；画板只画 Tenon 有差异的、或 Tenon 特有的部分。这类条目在表里打 B。
- 规格来源是仓库外的私有拆解包（见 [README](README.md)）。本文只写行为描述、结构描述与 aria-label 文字，不含任何第三方 class、令牌值或字体名。

## 处理规则

每条差异打一类：

| 类 | 含义 | 判定标准 |
|---|---|---|
| **A** | 画板层面已修 / 待修 | 差异会改变 Tenon 自己的信息架构、状态机或产品语义——不画出来就没法定实现规格。Tenon 特有（extra · tenon_specific）且需要确认位置或共存规则的，也归 A 并标「保留」 |
| **B** | 实现阶段照 fixture 做 | 与 Claude 语义完全一致、没有 Tenon 决策余地的菜单、弹层、确认框、标准交互。画板不画，实现时按 fixture 大纲逐项还原 |
| **C** | Tenon 不做或替代 | 语音听写与语音模式、Design / Code 双壳、套餐购买与「下载应用与扩展」、Drive 打开；Claude 的 Devices 一律替换为 Tenon 的「运行位置：本机」 |

计数：A 102 条、B 17 条、C 8 条、重复 1 条。C 另有 5 条落在第 4 节的块词汇里（深度检索一族）。

`extra` 且属于 Tenon 特有的条目，处理列写「保留」——它们不是缺陷，但要确认没有顶掉 Claude 元素的位置。

## 块词汇

给 assistant-ui 组件实现看的那一层：消息流里每种块的状态、与 Claude 的关系、以及落地规格。关系取值 `match`（形态一致，只差细节）/ `differs`（同一件事做法不同）/ `missing`（Tenon 没有）/ `tenon_only`（Tenon 特有，Claude 无对应）。深度检索一族按处理规则 C 不做，条目保留以说明取舍。
