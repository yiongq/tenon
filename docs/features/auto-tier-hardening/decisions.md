# 开自动档前的加固 · decisions

范围三项（D1–D3）与起草后的四个取舍（D4–D7）都由 owner 2026-11-08 按推荐定（picks.md）。开放问题一节已清空。

### D1 · `.git` 保护拦什么
- A ★ 只拦转向文件：commondir、config.worktree、子模块与 worktree 的 git 目录、已有的 `.git` 指针文件及它指向的配置和钩子；沙箱里根下照常 git commit/checkout/stash。子目录新冒出的 `.git`：macOS 直接拦，Linux 拦不住、实测后写进已知限制。
- B 整个 `.git` 只读，沙箱里 git commit 等全部失败。
- 选错难退吗：难退。拦的粒度决定了沙箱里哪些 git 操作能用；放宽（从 B 回 A）要 owner 点名。
- 结果：选 A · 2026-11-08（owner picks.md）。拦到文件还是整目录的细粒度见 D4。

### D2 · 连接器外带何时出卡
- A ★ 跨来源才出卡：连接器结果算不可信内容、读到的算私密数据（两形态都算）；会话里既有不可信内容又有来自别处的私密数据时，调任何连接器（含「总是允许」）出一张只管这一次的外带卡；同源读写不算外发。
- B 用过连接器之后每次调连接器都出卡。
- 选错难退吗：中。判据写进外带 inspector，改判只影响后续调用、不迁移数据。
- 结果：选 A · 2026-11-08（owner picks.md）。「出口」范围与「私密粒度」见 D6、D7。

### D3 · 钩子位置名单
- A ★ 配置加常见钩子工具：认 `core.hooksPath` 指的目录（仓库 `.git/config` 与全局 git 配置），再加 `.husky/`、lefthook.yml 一族、`.pre-commit-config.yaml`；文件工具写这些每次出卡、卡上写「会被自动执行」；沙箱里的命令也不能写。
- B 只认 `core.hooksPath`，沙箱侧照旧。
- 选错难退吗：易退。名单是加法，增删名字不迁移数据。
- 结果：选 A · 2026-11-08（owner picks.md）。`.husky/` 照本卡按名字无条件保护（Codex 评审 1）。沙箱一侧两平台都拦每个根下已存在与尚不存在的钩子位置及解析出的 `hookDirs`，macOS 另拦子目录同名位置；Linux 上根下尚不存在的由 srt 空占位挡住，P4 实测代价与 04 已有占位同类、正常 git 不坏，所以照卡执行，不另出卡。Linux 上子目录同名位置拦不住（srt 丢弃通配写规则，E7），与 D5 同属「Linux 做不到」一类，照 D5 由 06 对 Linux 沙箱命令照样出卡。

### D4 · 子模块与 worktree 的保护粒度
- A ★ 只拦配置和钩子文件：拦这些 git 目录里的 config、config.worktree、commondir、hooks；子模块里照常提交；沙箱里 `git submodule update`、`git worktree add` 失败，要到沙箱外跑（macOS；Linux 上 worktree add 照常，P2）。
- B 整个 `.git/modules`、`.git/worktrees` 目录不可写。代价：另加「子模块内提交失败」（P1：macOS 整目录拦时 sub-commit rc=128）。
- 选错难退吗：难退。决定沙箱里哪些 git 操作能用；放宽要 owner 点名。
- 结果：选 A · 2026-11-08（owner picks.md「只拦配置和钩子文件」）。攻击面与 B 一样（都挡掉改 config/hooks 的转向），代价更小。

### D5 · Linux 上「新建转向文件/子目录 .git」拦不住怎么办
- A ★ Linux 自动档的命令照问：写进已知限制；06 在 Linux 上只放宽原本就符合自动档条件的普通文件工具操作，敏感位置（`.git/**`、钩子位置等 05 名单里的位置）仍每次问，沙箱里的命令仍出卡、卡上说明原因，直到有办法补上；macOS 不受影响。
- B 为堵它在 Linux 上把整个工作区根 `.git` 设为拒写。代价（按机制推断，未单独实测）：`.git` 已存在，Linux 上是只读绑定、不产生占位，但沙箱里根下的 git 写操作（commit、checkout、stash 等）全部失败，即 owner 卡 1 的另一项「整个 .git 只读」；而且它只挡得住根 `.git` 里的新建，挡不住子目录新建 `.git`。
- 与 B 无关、另记的实测：P2 的 REDIR 变体（给**不存在**的 commondir/config.worktree 叶子加拒写）会用 `/dev/null` 占位破坏所有正常 git（根 status/add/commit 全 rc=128、宿主 git 在命令期间 fatal、强杀留占位）。这是规矩 3 只拦已存在条目的依据，不是 B 的代价。
- 选错难退吗：中。是 06 的放行范围约定，改判不迁移数据，但影响用户在 Linux 上的自动档体验。
- 结果：选 A · 2026-11-08（owner picks.md「Linux 自动档的命令照问」）。B 让沙箱里的 git 写操作全部失败、又补不全子目录的缺口，不取。写进 spec §给 06 的约束。

### D6 · 连接器的「出口」范围
- A ★ 任一连接器调用都算潜在出口（含读类），按规矩 4 判。
- B 只把「看起来会写/发送」的连接器调用算出口。代价：要靠连接器自报的注解判读/写，而注解是不可信输入（AGENTS.md 硬规矩「注解不得放宽权限」），会被投毒绕过。
- 选错难退吗：难退。决定哪些连接器调用触发外带卡；收窄（从 A 回 B）会放宽检查，要 owner 点名。
- 结果：选 A · 2026-11-08（owner 不另问，picks.md）。B 依赖不可信注解，违反硬规矩。

### D7 · 连接器结果算私密 + 不可信的粒度
- A ★ 每个连接器调用的结果一律既算不可信内容、也算私密数据（按 serverId）。
- B 按可逆性/注解细分哪些连接器结果算私密。代价：同 D6-B，依赖不可信信号。
- 选错难退吗：中。改判只影响后续调用、不迁移数据。
- 结果：选 A · 2026-11-08（owner 不另问，picks.md）。与 owner 卡 2「结果算不可信、读到的算私密」一致，且不依赖不可信信号。
