### D1 · 命令的「没法替你撤回」怎么改

背景：命令跑之前的审批卡、跑完后的工具行都写「如果它改了东西，Tenon 没法替你撤回」；任务文件夹能整体拍快照时，同一轮的结算行却写「可还原」，两句打架（06 第 24 步实机验收发现）。05 的 D8 定过「命令的卡不标『有快照』」，理由是命令跑之前还不知道这一次快照拍不拍得成。

- A ★ 卡和行都按实情说：工具行在这条命令有快照号时说改的文件能随这一轮还原；审批卡在会话快照是整个文件夹时说「一般能」；都写明联网发出的、`.git` 里的、被排除的文件撤不回。卡上仍不出「有快照」那句，但意思往能还原靠，算对 D8 的放宽 — 代价：卡上的「一般能」在首张快照没拍完或这一次拍失败时不成立（结算行会另写「命令的改动可能无法还原」）。
- B 只改工具行，审批卡一字不动（D8 原样） — 代价：卡上那句仍和结算行打架，只是挪到跑之前。
- C 两处都换成不下断言的中性句「命令做的事，Tenon 不一定撤得回。」 — 代价：用户看不出其实能还原，只能看结算行。

选错难退吗：不难。只是 renderer 里选哪句文案，改回去是一次小改动，不碰存盘与契约。
结果：A · 2026-11-28。

## agent 自定

- 自定：卡上的新句只给整树快照（`tree`）的会话 · `warming` 时首张还没拍完，命令的改动可能还原不了；`file-only`、`unavailable` 时命令的改动不进快照（05 §已知限制与代价） · 照实情说就只剩 `tree`。
- 自定：子任务卡与子任务里的工具行照旧用旧句 · `snapshot.rounds` 的 `calls` 只列根会话的改动调用，子任务的命令拿不到快照号；卡上也不区分 · 宁可少说能还原，不多说。
- 自定：工具行看这次调用有没有快照号，不看这一轮现在还能不能还原 · 快照清掉之后快照号跟着消失、旧句又成立；已经还原过的轮，「能随这一轮还原」仍是实情。
- 自定：文案里点名 `.git` · 05 §已知限制与代价：命令里的 `git commit`、`reset` 改的就是你自己的 `.git`，还原不了；只写「被排除的文件」用户会以为 `.git` 也在快照里。
- 自定：档位 standard · 换的是审批卡上说后果的那句，属权限语义的文字；判定、按键、期限与契约都不变，不到 heavy 的条件；替换 implemented 的 presentation-r1 条款要走一份 spec。
