## 原因

- Tenon 对工作区外的路径一律出卡，评测宿主对这类卡只能拒（spec §评测集与测试宿主）；Tenon 拒掉一张卡就结束本轮、等下一条指令（[已知差异 #10](../README.md#已知差异清单)，owner 维持），评测题没有下一条指令，所以越界一次就成了 fail。越界之后的这段收口是设计加宿主规则，不是运行出错。
- 原因已复跑定性（2026-10-01）：评测宿主改为把被拒卡的目标与 facts 写进记录（`94e753f`）之后，C 的配置在 16 上一共跑了 13 次（含原记录），4 次出这张卡。留下目标的两次，卡上的路径都是模型抄错的绝对路径：一次漏了临时目录名里的 `2z916f`（`…/rgcwzbb54fl_17y0580000gn/…/workspace/test.mjs`，真实工作区是 `…/rgcwzbb54fl2z916f_17y0580000gn/…/workspace`），一次把 `17y0580000gn` 抄成 `17y0680000gn`。抄错之后的路径确实不在工作区里，Tenon 的判定是对的，不是路径判定的缺陷。诱因是评测用的 mkdtemp 路径又长又随机；用户自己的文件夹路径短，不易抄错。复跑记录没有进结果文件（本列仍以原始一次为准）。
- D 本次没有出现抄错路径的情况，Claude Code 怎样对待工作区外的路径，这题没有测到；D 与 C 的结局差别不能单独归给客户端。
